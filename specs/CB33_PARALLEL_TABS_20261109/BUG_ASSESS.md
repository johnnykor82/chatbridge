# CB33 BUG ASSESS — 2026-11-09
Symptom: concurrent initial Watcher sessions can fail before send with Page.goto: net::ERR_ABORTED / frame detached. Engine uses asyncio.Semaphore(10), per-session locks; browser transport has global connect_lock only for Chrome connection, not page allocation. Suspect simultaneous context.expect_page listeners capture wrong event (same page). Proposed remediation: narrow creation/identity lock + exact targetId validation, no global navigation/send lock. Need reproduce with fake browser concurrent CDP session and page events in 2/3/5/10 offline tests before implementing. Rollback and test gates per PLAN.

Evidence from RED test 2026-11-09: concurrent _new_page calls each register a context.expect_page waiter, fake Chromium publishes first created Page to all waiters, every call returns same Page for n=2,3,5,10. No actual targetId comparison and no target cleanup after cancellation. This deterministically establishes architectural race. Single-tab normal path does not reveal it. Bug Assess: VERIFIED; narrow creation lock, strict targetId matching, bounded cleanup needed.
