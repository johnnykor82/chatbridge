# Архитектура CB34 — 2026-11-19

Сохраняем существующий поток `BrowserTransport.generate -> Engine -> Store`, event `send_attempted`, привязку оригинального POST к полному prompt и state `unknown`. Применяем **до отправки** `_select_native_send` с приоритетом CSS `button[data-testid="send-button"]`, role name `Send/Отправить`, известные aria-label; строго проверять видимость+enabled единственного контроля, иначе `RuntimeError("native_send_unavailable_before_attempt")` без `send_attempted`. Enter без подтверждения режимом отправки больше не использовать. Добавить проверку заполненности редактора и наличие вложений, не меняя содержимое.

После `send_attempted` выполняем один click, ставим монотонный deadline <=60s для *первой* source-bound HTTP 2xx + user-ID квитанции. Если POST не обнаружен, выбрасываем `SubmissionUncertainError` с диагностикой `no_verified_post` и локальным снимком состояний кнопки/редактора без prompt. Если POST наблюдался, но ответ неизвестен, также `unknown`; не ретраить. После подтверждения работают существующие длительные thinking/streaming/approval/turn-completion лимиты.

Уровни логирования: INFO stage+time, WARNING stage+uncertain outcome; не логировать текст, cookies/authorization. Магистраль Engine.persist сохраняет исходную попытку до click. Добавить bounded request status diagnostics для сигнализации клиенту (не меняя медицинский JSON). Мониторинг медицинской задержки использует уже существующий scheduler/notifier и stale status, а не новый повторный send.
