# CB34 — Надёжная отправка ChatBridge (v1, утверждено владельцем 2026-11-19)

## Проблема
Медицинские запросы 10314/10315: открыта страница проекта ChatGPT, затем нет исходного POST, client user ID или ответа; шлюз 30 минут молча ждёт `end_turn`, после чего `unknown`. Вероятный сбой — ненадёжный fallback Enter в редактор, когда нативная кнопка Send не распознана (иконка/другое имя); точная причина требует теста.

## Требования
- **R1.** До попытки отправки однозначно проверить авторизацию, принадлежность Project, готовность редактора, заполнение текста, готовность всех вложений и наличие *действительно доступного нативного* Send; проблемный pre-send должен быстро завершаться доказанным `not_sent`, без запроса модели.
- **R2.** Выполнить только **одно** пользовательское действие Send. Не заменять отсутствие кнопки слепым Enter, который может вставить новую строку. Если Send недоступен, не помечать `send_attempted`.
- **R3.** Сразу зафиксировать локальную попытку и источник исходного POST; подтвердить выполнение только оригинальным HTTP 2xx + связанным user message ID. При потере подтверждения после клика оставлять `unknown` (не повторять), но ограничить ожидание подтверждения примерно 60 сек, сохранив длительное ожидание только для *подтверждённо отправленной* генерации.
- **R4.** Записать структурированные события по стадиям (navigation, authentication, model, editor, attachment, composer, preflight, click, post, assistant) с elapsed_ms, безопасным классом причины и request_id, не записывая prompt/медданные/токены. Отдельно сохранять диагностическое резюме при сбое; чувствительных скриншотов в обычные логи не помещать.
- **R5.** Не допускать дублей при timeout, HTTP 429, потере сети, непонятном результате клика и перезапуске; сохранить durable исходные request_id/intent/дедупликацию. Для гарантированного `not_sent` разрешено повторить только до Send, для `unknown` запрещено.
- **R6.** Клиенты должны своевременно обнаруживать задержку отчёта (>10 мин), сохраняя неотправленные оригиналы и объединяя медицинские циклы как раньше; существующие медицинские данные/контракты не теряются.
- **R7.** Тесты: icon-only native Send, отключённая кнопка, login expired, async attachment, editor/Send mismatch, missing POST after single click, delayed ACK, source-bound matching, provider timeout, restart, ten consecutive missed cycles; вся существующая регрессия.
- **R8.** Converge, rollback, Git commit+push to `johnnykor82/chatbridge`, install same release on **Mac Server** and **jkmac**, проверить версии/launchd/health на обеих, test isolated flow без дублирования медицинского запроса.

## Критерий приёмки
Каждый сбой до Send классифицирован как безопасно неотправленный; после Send неизвестный исход не превращается в дубликат; не существует 30-минутного молчаливого ожидания без POST. Успешный provider POST имеет проверенную связанную квитанцию; обе установки совпадают с опубликованным SHA.
