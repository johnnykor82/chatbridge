# CB35 — восстановление медицинского Telegram-агента (v1, 2026-11-20)
## Наблюдаемая проблема
После beta25 отчёты #10316/#10318 (26k символов + 3–4 JSON вложения) восемь раз завершались до физического клика с `native Send control unavailable before attempt`; нет user/assistant IDs и отправки в Telegram. Предыдущие #10314/#10315 имеют `unknown` и повторять их отдельно нельзя. Финальный накопительный #10318 `failed`, три дочерних отчёта `coalesced_failed`.
## Требования
R1. Установить по данным реального браузера точную причину отсутствия Send **после** заполнения того же замороженного медицинского пакета, не нажимать Send при диагностике.
R2. Fix только подтверждённой причины: ограниченное ожидание подлинной готовой кнопки, корректная уникальность видимых элементов и состояния вложений; не вводить слепые Enter, не обходить disabled/защиту поставщика.
R3. До любых изменений проверить медицинский и ChatBridge бэкапы с rollback; никакой повторной отправки `unknown` и никаких потерь frozen clinical context.
R4. Восстановить ровно один накопительный #10318 через штатный бот (либо новый безопасный owner) только после подтверждения, что последняя попытка #10318 не отправлялась; сохранить все идентификаторы и историю; 10314/10315 не пересылать отдельно.
R5. Дождаться реального завершения ChatGPT, строгой медицинской JSON/anomaly/document validation и **Telegram chunks_sent + ACK**, затем подтвердить дочерние циклы и пустую очередь.
R6. Регрессии и негативные тесты (large composer, disabled send, duplicate candidates, delayed upload, uncertain post, retry and restart), lint; Spec Kit Analyze/Converge, актуальные PLAN/backlog/docs, Git commit; при изменении ChatBridge — push GitHub и install одинаковой версии на обеих Mac.
R7. Не вмешиваться в другие службы, ChatGPT аккаунты, медицинские записи и Telegram credentials.
